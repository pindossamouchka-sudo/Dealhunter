## Варианты размещения в РФ

### Вариант A (рекомендуемый): российский managed Postgres + приложение в РФ
1. Провайдер: managed PostgreSQL у российского провайдера (Selectel / Timeweb Cloud / Yandex Cloud / VK Cloud) + хостинг приложения в РФ-регионе.
2. Что в коде: для смены БД менять код не нужно (DATABASE_URL из окружения). Желательно отдельно: собрать чтение всех ключей env в один конфиг-модуль, чтобы база/URL не расползались по файлам.
3. Миграция: скрипт `scripts/migrate_transfer_data.py` (подготовлен, НЕ запускается автоматически; см. ниже).
4. 152-ФЗ: после переноса первичный сбор идёт в РФ (ст. 18 ч. 5); уведомление РКН об обработке; вопрос бэкапов Neon после переноса — закрыть запросом в их поддержку об удалении проекта и бэкапов (см. раздел «Как проверить, что старые данные удалены»).

### Вариант B: двойная запись (только переходный период ~2–4 недели)
1. Приложение пишет в РФ-БД; отдельный worker копирует в Neon только НЕ-ПД данные (лоты dh_lots). ПД НЕ дублируется.
2. Сложности: два источника истины, рассинхрон. Долгое состояние не рекомендуем.

### Вариант C: остаться в США
Уведомление РКН о трансграничной передаче (см. docs/rkn_notification_draft.md, часть 2) + обоснование. Риск: претензия надзора при масштабной рекламной кампании; допустимость текущей схемы — вопрос для юриста.

## Миграция (скрипт и тест)

Файлы:
- `scripts/migrate_transfer_data.py` — ручная миграция: подключается к SOURCE_DATABASE_URL и TARGET_DATABASE_URL, создаёт схему на цели, копирует таблицы в порядке (dh_users → dh_monitors → dh_monitor_hits → dh_lots → dh_payments → dh_promo_used), печатает сводку «скопировано / осталось на источнике». НИЧЕГО не удаляет на источнике.
- `test_migrate_transfer_data.py` — тест на имитации пустой базы (fake-conn): корректный порядок SQL, безопасный отказ без MIGRATE_CONFIRM=YES, нулевые счётчики на пустой базе.

## Как проверить, что старые данные удалены (после переноса, вручную)

1. На старом источнике (только после письменного подтверждения владельца) выполнить:
   `SELECT 'users', COUNT(*) FROM dh_users UNION ALL SELECT 'monitors', COUNT(*) FROM dh_monitors UNION ALL SELECT 'hits', COUNT(*) FROM dh_monitor_hits UNION ALL SELECT 'payments', COUNT(*) FROM dh_payments UNION ALL SELECT 'promos', COUNT(*) FROM dh_promo_used;` — ожидание: все счётчики 0.
2. Запросить у Neon полное удаление проекта и бэкапов; срок хранения их бэкапов уточнять в панели поддержки (не выдумывать).
3. Переиздать секреты WORKER_SECRET/PROMO_SECRET после переезда.
